# GenDX_T · 本地设备检测记录

本项目按附件《副本 GenDX_T》重新组织首页、患者录入、拍摄、结果和历史流程，网页与 Android 共用源码和浅色界面。当前版本为 **1.1.0**，Android `versionCode` 为 **11**。

本次将按钮、导航、选中状态及配套浅色底色恢复为旧版蓝色主题（主色 `#2855dc`）。保留新版布局、检测流程与 GenDx Logo；依用户要求，本次版本保持 **1.1.0 / 11**。

首页设备图已替换为用户提供图片的无水印版本 `public/gendx-device.png`。患者性别和检测项目使用统一下拉菜单；表单聚焦蓝框直接贴合边缘，所有文本/下拉控件高度减少 3px（患者框桌面 46px、移动端 44px）。首页已去除设备图下方的重复品牌/标语文案，Enter（中文“开始检测”）在按钮中间对齐，右箭头独立靠右。这些资源和样式由网页与 Android 共用。Android Studio 当前模拟器使用保留原记录覆盖更新的 1.1.0 调试版。

首页底部的本机处理说明已移除；设置页去除副标题、默认导出格式、本机记录数量和底部提示，只保留语言、隐私和关于入口。中英文同步精简，导出弹窗仍可选择全部支持的格式。

患者表单恢复 **Take photo / Upload photo** 两个入口，所有屏幕同一行等宽并列，启用、禁用和交互状态共用蓝色按钮样式。每次上传一张 JPG、PNG 或 WebP（不超过 20 MB）；Android 使用系统文件选择器，无需新增相册或全盘存储权限。

默认使用本地网页版与离线 Android APK，无需账户、后端或云端识别服务；本次修改不发布远程站点。iOS 尚未打包交付。

本次源码检查、资源同步、正式 APK、模拟器和真机验证分别记录在 [版本与 Android 验收记录](ANDROID-VALIDATION.md)。构建通过不代表设备实测通过。

## 文档流程与页面

底部导航为 **历史 / 首页 / 我的**。患者录入、拍摄和结果属于一次新检测的连续步骤，不再作为独立底部入口。

| 附件中的流程 | 当前实现 |
| --- | --- |
| 首页与 Enter | 展示 GenDx Logo、设备参考图，点击 Enter / 开始检测进入空白患者表单 |
| 信息录入 | 六项信息必填，通过校验后才能拍照或上传照片 |
| Take Photo | 实时相机画面带设备、试管条码及灯位参考框 |
| Upload Photo | 网页文件选择器 / Android 系统选择器选一张已有照片，复用同一识别与保存流程 |
| 照片结果 | 展示患者信息、样本条码、时间、照片标注及设备指示；可确认保存或重新录入并拍照/上传 |
| 历史与详情 | 搜索、筛选、查看只读记录，选定或全部导出 |
| 我的设置 | 切换 English / 简体中文，查看隐私、关于和版本 |

默认界面语言为英语，可在设置切换简体中文，语言保存在本机。导出时在弹窗中选择格式；若本机已有旧版默认格式偏好，仍读取为弹窗初始选项。既有算法错误、历史文本和导出字段保留其实际内容，不通过切换语言改写记录。

## 一次检测如何保存

1. 点击 **Enter / 开始检测**，每次都会清空上次患者表单。
2. 填写患者名字、性别、年龄、患者编号、联系方式、检测项目。年龄为 0–150 岁的整数；其他文本必填。
3. 检测项目仅提供 **MTB、GBS、Flu A、Flu B、NG、MG、CT**。表单未填完整时拍照和上传均不可用。
4. 选择拍照，或上传一张包含完整机身与试管条码的照片。原始照片及本次患者信息先保存到本机，再识别条码和灯态；两入口共用后续处理。取消选图、格式/大小无效或图片无法解码时保留草稿，允许重选，不创建记录。
5. 结果页展示本次照片的分析结果。点击 **Confirm result / 确认并保存**记录确认时间并锁定结果；此操作不能修改条码、患者信息或灯态。
6. 需要重新拍照或上传时点击 **New photo / 重新拍照或上传**，重新填写患者信息，建立一条新记录；原记录保留。同一照片也可用于下一次独立录入，不会覆盖旧记录。结果页底部不再重复提供 Home / History 按钮，使用固定底部 Tab 切换。

每张照片对应一次独立患者录入，不提供批量套用患者信息、手动改条码、改灯态、框选重算或删除记录的界面。

照片进入本机存储后，即使未点击确认就返回首页或退出应用，也会保留。未确认记录在导出中保留未确认状态，不会自动成为已确认阳性或阴性。历史详情只读，不能补改信息或继续确认旧记录；需要重做时创建新检测。

若照片分析在退出时中断，重新打开后保留照片和患者信息，并显示处理中断。返回首页重新录入，再拍照或上传，不覆盖旧证据。照片或结果写入失败时会提示存储错误，需处理存储问题并重新打开应用。

## 结果规则与拍摄范围

- **Negative、Positive、Invalid 三个结果灯互斥，最多一个亮起。** 不使用 Invalid 覆盖其他结果灯的优先级。
- 单独 Negative 亮起为阴性指示，单独 Positive 亮起为阳性指示，单独 Invalid 亮起为无效指示。
- 结果灯缺失、未定位、未知、全灭或无法可靠排除串光时，保留待确认；旧记录出现多结果灯同时亮起时显示冲突待确认。
- **Power 只展示电源状态。** Power 亮、灭、未知或缺失均不影响结果、待确认判断或提示。
- 用户确认只锁定原识别信息。识别完成、有条码且结果灯明确时才设置已确认标记；处理失败或不确定记录仍不会变成确定阴阳结果。
- 仅适配参考中的蓝盖四灯设备。严重反光、遮挡、透视或其他型号可能无法可靠识别，应重新录入并拍摄。

算法使用设备布局和局部光学信号定位灯位，条码由 ZXing-C++ WebAssembly 从图案解码并保留前导零；不通过 OCR 猜测条码，不伪造模型置信度。结果描述设备灯态，不自行推导患者诊断。

网页与 Android 共用实时相机组件。参考框仅辅助对齐，不自动保证对准，也不裁剪原始画面；实际照片尺寸取视频流可用尺寸，不等于系统相机最高静态拍照分辨率。拒权、占用或相机超时会提示重试；关闭或进入后台会释放镜头，返回后需主动重启相机。网页相机需要 HTTPS 或 localhost。

## 历史、导出与数据语义

历史页支持按患者名字、患者编号、检测项目或样本条码搜索，并按结果筛选。可以选择当前列表中的记录后导出，也可以导出全部本机记录；没有旧版“最多保留 30 张”的界面限制。记录增长仍受本机存储与内存容量限制。

| 格式 | 内容与用途 |
| --- | --- |
| Excel `.xlsx` | 患者六项信息、照片缩略图、条码、结果、逐灯状态、确认及锁定时间、原始设备指示 |
| CSV `.csv` | UTF-8 BOM；元数据、统计和逐条记录，以文本保护保留编号等内容 |
| HL7 v2 `.hl7` | HL7 v2.5.1 `ORU^R01` 离线消息批次，包含患者、项目、状态及逐灯数据 |
| FHIR JSON / XML | FHIR R4 `Bundle(type=collection)`；本地术语、软件 Device、已有患者信息的 Patient、Specimen 与 Observation |

各格式都保留原始灯态和处理/确认状态。失败、处理中、条码缺失、未确认、灯态不确定或冲突的记录不输出确定阴阳主值；Invalid 也不作为有效阴性或阳性。旧版本的人工信息来源会作为历史数据保留。

患者编号、联系方式及条码保持文本语义；CSV 会对易被表格软件执行或改写的字段添加英文撇号保护，程序导入时需去掉该保护前缀。年龄为录入年龄，不推算出生日期。页面时间来自本地记录创建时间；导出区分创建时间与确认保存时间，不伪造采样时间或临床检测时间。

统计只覆盖本次选定的导出范围。一条记录代表一次照片处理；处理失败率为 `失败 / (完成 + 失败)`，不是临床误判率，也不代表实体设备累计使用次数。

HL7 / FHIR 使用应用本地术语，未虚构 LOINC、SNOMED 或检验仪序列号。交付的是离线文件，接入医院系统仍需接收方字段映射与联调，未实现在线 HL7 传输或医院认证。

Android 的保存操作打开系统文件位置选择器，可选择系统提供的下载目录或 OTG / U 盘；分享操作交给用户选择的应用。选择分享目标不等于接收方已经保存或发送成功。网页版优先使用文件保存接口，不支持时触发下载；发起下载不表示已写入指定目录。取消保存或分享不会删除本地记录。

## 本机存储与旧版升级

网页记录保存在当前浏览器和站点的 IndexedDB；Android 记录及原图保存在应用私有目录，使用原子写入。两端各自存储，不自动互传。未提供账户、远程同步或信息上传。

同签名覆盖升级保留已有记录。应用包名仍为 `com.jiantu.inspection`，原存储目录与数据库名称不变。旧版没有患者信息的记录显示为历史旧记录，继续查看与导出，不虚构或补填患者，不允许修改或删除。

原始照片、患者信息和历史结果受共享存储层与 Android 原生桥双重只读保护。卸载应用、清除应用数据或清理浏览器站点数据仍会移除记录。导出包含患者信息，请妥善保存；Excel 缩略图不是可恢复原图的完整备份，本版没有文件导入恢复功能。

## 根目录运行与构建

环境：Node.js **22.13+**；Android 构建额外需要 **JDK 21** 与 **Android SDK 36**。依赖安装和首次构建可能联网；安装后的 APK 内置界面、品牌图与条码 WASM，可离线运行，不加载远程站点。

```sh
npm ci
npm run dev
```

浏览器访问终端显示的本地地址。网站生产构建与必要检查：

```sh
npm test
npm run typecheck
npm run build
```

Android 资源同步与正式构建：

```sh
npm run android:sync
node scripts/build-apk.mjs release
```

也可用 `npm run apk:release` 一次执行资源同步和正式构建。若同一份源码的资源同步已成功，直接运行打包脚本即可，无需重复同步。`npm run apk:debug` 构建调试包。

正式 APK：`releases/GenDX_T-1.1.0-release.apk`；校验文件：`releases/GenDX_T-1.1.0-release.apk.sha256`。本版源码检查、资源同步、正式构建、原签名校验及设备实测的完成状态见 [验收记录](ANDROID-VALIDATION.md)。

Android 支持 API 24 / Android 7.0 及以上，系统 WebView 需要支持当前页面和 WebAssembly；开启相机时才申请相机权限。原生 Manifest 不申请网络、麦克风或全盘存储权限。

`JAVA_HOME` 与 `ANDROID_HOME` 可指定本机环境；脚本默认检查 macOS Android Studio 自带 JDK 和用户目录下的 Android SDK。Android Studio 的 Run 不会自动更新网页资源，修改共享源码后应先执行 `npm run android:sync`。

正式构建必须复用现有 `signing/jiantu.jks` 与 `signing/keystore.properties`。禁止生成或替换密钥；签名文件缺失时应从原备份恢复。`signing/` 已忽略 Git，私钥与密码不随 APK 分发。后续交付默认递增 `android/app/build.gradle` 的 `versionCode` / `versionName`；本次依用户明确要求保持 `1.1.0 / 11`。

已安装正式版的设备使用同签名 APK 覆盖升级，例如：

```sh
"$HOME/Library/Android/sdk/platform-tools/adb" devices -l
"$HOME/Library/Android/sdk/platform-tools/adb" -s 实际设备序列号 install -r releases/GenDX_T-1.1.0-release.apk
```

调试包与正式包签名不同，不能互相覆盖；不要为解决签名冲突卸载仍有本地记录的应用。模拟器检查与真机检查分别记录。

Android Studio 的现有模拟器使用调试签名。需要更新时，在项目根目录完成同步及调试构建，再覆盖安装（将设备序列号替换为实际设备）：

```sh
npm run apk:debug
"$HOME/Library/Android/sdk/platform-tools/adb" -s emulator-5554 install -r releases/GenDX_T-1.1.0-debug.apk
"$HOME/Library/Android/sdk/platform-tools/adb" -s emulator-5554 shell am start -S -n com.jiantu.inspection/.MainActivity
```

当前模拟器的覆盖安装、启动与原记录保留已验证；下拉交互在网页版完成检查，尚未完成 Android 下拉交互及真机摄像头验收。
